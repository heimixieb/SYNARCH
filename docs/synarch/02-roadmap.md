# SYNARCH 开发路线

目标：以 OpenMausBot 为唯一基础，二次开发成 DeepSeek 理念的 Super-agent——你只和总管说话，总管调度所有模型完成工作，只在需要你决定或验收时才找你。

## 开发原则

1. **上游优先。** 通用问题（中文记忆、凭证开关）修好后提交给官方，被合并后我们就不用自己维护。只有 SYNARCH 独有的功能才留在自己分支。
2. **少改核心，多加新文件。** 新功能尽量放在新文件里，减少和官方每天更新的冲突。
3. **固定版本开发。** 当前基于 v0.1.151，分支 `synarch/main`。每个阶段结束时再评估是否跟进官方新版本。
4. **不碰真实数据。** 所有验证在临时测试环境里做。
5. **订阅安全第一。** 只用官方命令行和正规 API，不提取令牌、不轮换账号绕额度。
6. **每完成一个能用的功能就存档（git 提交）。**

## 阶段 1：修两个硬伤

**1.1 中文记忆检索（缺口 1）**
- 先查上游是否已有人在修，有的话直接用或一起完善。
- 方向：给中文单独建一个按字切分（trigram）的搜索索引，查询时中文按词或按字匹配，英文保持原样。
- 完成标准：上游 Issue 里的 20 条中文测试，命中率从 0 提升到绝大多数；原有英文测试全部通过。
- 完成后提交 PR 给官方。

**1.2 Claude 凭证开关（缺口 2）**
- 加一个设置：不读取 Claude 登录凭证。SYNARCH 默认关闭读取。
- 关闭后：不显示 Claude 额度条；额度用完时靠真正被拒绝再切换引擎（现有机制已支持）。
- 完成后提交 PR 给官方。

## 阶段 2：超级总管

**2.1 全局任务看板（缺口 4）**
- 把委派、目标、定时任务统一成“工单”视角，状态只用这几种：等你回答 / 等你验收 / 受阻 / 失败 / 排队中 / 工作中 / 空闲。
- 一个页面列出所有工单，需要你处理的排最前面，一切正常的不占地方。
- 总管也能查看这个看板（新增一个工具），汇报时能说清楚每件事的状态。

**2.2 独立验收（缺口 3）**
- 目标完成前，自动开一个不同厂家的模型来检查。默认“不信任”：找到问题就打回，检查不了就交给你决定。
- 上游计划文档已有设计（goal-mode-v2 第 5 节），照着实现。

**2.3 全局总管**
- 先用现有的“也负责这些部门”把一个总管扩展到全部门，看够不够用。
- 不够再按上游 Issue #597 的设计做“总管的总管”。

## 阶段 3：智能调度（缺口 6）

- 先做最简单的：在总管的工作规则里写清楚“谁擅长什么、什么活用便宜模型、什么时候必须换一家复查”。
- 再做有数据支撑的：记录每个模型做各类任务的成功率、耗时、花费，总管据此分派。
- 研究 HiRoute 能否作为底层路由接入；不能就只借鉴它的规则。
- 额度用完的切换沿用现有机制。

## 阶段 4：主动工作（缺口 5）

- 给触发器加三档：关闭 / 观察 / 自动。默认“观察”：只记录“本来会做什么”，不动手。
- 规则用中文写给总管看（比如“淘宝订单异常时帮我查原因”），不做成一堆设置项。
- 你在看板上看观察记录，觉得靠谱再改成自动。

## 现在不做的

- 不另外引入独立的总管程序（如 Hermes），避免两个 AI 抢调度权。
- 不把其他开源项目的代码直接拼进来。
- 不做手机端、云端部署，等核心能力稳定再说。
