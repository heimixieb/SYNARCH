# SYNARCH 开发路线

目标：以 OpenMausBot 为唯一基础，二次开发成 DeepSeek 理念的 Super-agent——你只和总管说话，总管调度所有模型完成工作，只在需要你决定或验收时才找你。

## 开发原则

1. **上游优先。** 通用问题（中文记忆、凭证开关）修好后提交给官方，被合并后我们就不用自己维护。只有 SYNARCH 独有的功能才留在自己分支。
2. **少改核心，多加新文件。** 新功能尽量放在新文件里，减少和官方每天更新的冲突。
3. **固定版本开发。** 当前基于 v0.1.151，分支 `synarch/main`。每个阶段结束时再评估是否跟进官方新版本。
4. **不碰真实数据。** 所有验证在临时测试环境里做。
5. **订阅安全第一。** 只用官方命令行和正规 API，不提取令牌、不轮换账号绕额度。
6. **每完成一个能用的功能就存档（git 提交）。**

## 阶段 1：修两个硬伤

**1.1 中文记忆检索（缺口 1）—— 已完成（2026-11-10），待提交给官方**
- 上游无人在修（Issue #5161 无 PR）。
- 做法：存入时在每个中文字之间插入看不见的分隔符（U+200B），让数据库能按字建索引；提问时把中文两字一组（去掉“的、了、是、什么、时候”等虚词）去匹配，按命中多少排序。英文完全不变。旧数据在升级后第一次打开时自动转换。
- 代码：新文件 `server/cjk-search.ts`；改动 `message-db.ts`、`message-db-memory-index.ts`、`recall.ts`、`memory-topics.ts`、`workspace-backup.ts`。
- 结果：自建 20 条中文笔记 + 20 个换说法的提问，**旧代码命中 0 条，新代码 20 条全中**；4 个无关提问中 3 个不带出任何笔记。
- 验证：类型检查、代码规范通过；直接相关的 36 个测试文件 747 个测试通过；官方记忆端到端测试（加了中文场景）在隔离环境通过。
- 已知不足：常见词（“一次”“到期”“上次”）偶尔带出不相关笔记，排在正确笔记之后。

**1.2 Claude 凭证开关（缺口 2）—— 已完成（2026-11-10），待提交给官方**

- 验证：类型检查、代码规范通过；相关 5 个测试文件全部通过；隔离环境里有 Claude 引擎时额度接口返回空列表（没读凭证）。

## 阶段 3：智能调度（缺口 6）

**3.1 调度规则 + 模型成绩单 —— 完成（2026-11-10）**
- 总管工作说明加了“调度”一段：简单、重复、量大的活派给便宜或快的模型的队员；难推理、写代码、错了代价大的给最强的；看成绩单优先用表现好的模型，老失败的就换掉；只是需要换个模型（不需要新专家）时，用 `start_thread` 指定模型开一个单独任务，不新建 Bot；重要成果（要发布的代码、涉及钱、要发出去的东西、你要据此做决定的）在说完成前，有别家模型就让别家复查。

- 已知不足：成绩单按模型算，不分任务类型；DeepSeek 没有内置公开价格，只显示实际花费（引擎有上报才有）。
**3.2 HiRoute 调研 —— 完成（2026-11-10）：不接入代码，借鉴规则**
- HiRoute（`higress-group/HiRoute`，Apache-2.0，Rust）是装在本机的独立“中转站”，夹在 Codex / Claude Code / DeepSeek Harness 和模型之间，每条新消息先问一个“判断模型”，再决定这一步用便宜模型还是强模型。
- 不接入的原因：它管“一个对话里每一步用哪个模型”，SYNARCH 总管管“每件活派给哪个队员”，两层互补，不必拼在一起；它要单独安装、配账号、多付判断模型的钱（你的决定）；通过中转站用 Claude/ChatGPT 订阅可能违反“订阅安全第一”，只配 DeepSeek 这类按量 API 才没问题。以后想试，可以让某个引擎走它的本机地址，SYNARCH 基本不用改。
- 已借鉴进总管调度规则：① 低分保护——便宜模型做砸了，返工交给最强模型，问题过去再交回；② 新模型逐步放权——新来的模型先做简单活，成绩好了再加难度。
**3.3 DeepSeek 价格 + 验收不再“自己查自己” —— 完成（2026-11-10）**

## 阶段 4：主动工作（缺口 5）—— 不做（2026-11-10 决定）

- 原因：主动工作本身官方已经有（定时、网页触发、应用事件），阶段 4 只是加“先观察后自动”的安全阀。你一个人用、主要直接找总管派活，没接邮箱、日历、网购订单让 Bot 无人值守地处理，这个安全阀用不上。
- 什么时候再考虑：接上邮箱、日历等数据源，并且想让 Bot 自己处理这些事件时。
- 原计划留作参考：

- 给触发器加三档：关闭 / 观察 / 自动。默认“观察”：只记录“本来会做什么”，不动手。
- 规则用中文写给总管看（比如“淘宝订单异常时帮我查原因”），不做成一堆设置项。
- 你在看板上看观察记录，觉得靠谱再改成自动。

## 现在不做的

- 不另外引入独立的总管程序（如 Hermes），避免两个 AI 抢调度权。
- 不把其他开源项目的代码直接拼进来。
- 不做手机端、云端部署，等核心能力稳定再说。
